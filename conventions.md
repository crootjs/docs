# CrootJS Coding Conventions

These rules are **mandatory** for any code built with CrootJS — whether written by hand or generated by an AI coding agent (Claude Code, Cursor, Copilot, etc). They apply to CrootJS's own repos (`lib`, `docs`, `examples`, `crootjs.github.io`) and to any project that imports CrootJS.

## 1. Separate HTML, CSS, and JS into their own files

- No inline `<style>` blocks in HTML. CSS lives in its own `.css` file, linked with `<link rel="stylesheet" href="...">`.
- No inline `<script>` blocks with logic in HTML. JS lives in its own `.js` file.
- No inline `style="..."` attributes. Use a class name and define the rule in the CSS file.
- No inline event handler attributes (`onclick="..."`, `onchange="..."`, `oninput="..."`, etc). Attach listeners in JS with `addEventListener` (or CrootJS's `onClick`/`onChange`/`onInput` helpers from `element.js`).

A page should look like this:

```html
<!-- index.html -->
<link rel="stylesheet" href="style.css">
...
<button class="copy-btn">Copy</button>
...
<script type="module" src="script.js"></script>
```

```js
// script.js
document.querySelectorAll('.copy-btn').forEach(btn => {
    btn.addEventListener('click', () => { /* ... */ });
});
```

Not like this:

```html
<!-- don't -->
<style> .copy-btn { ... } </style>
<button style="color: blue" onclick="doThing()">Copy</button>
<script> function doThing() { ... } </script>
```

**One exception**: loading a third-party library from its own CDN (e.g. Lucide icons, SweetAlert2) via a plain `<script src="...">` tag is fine — that's an external dependency, not inline application logic.

## 2. JavaScript must be loaded as an ES module

Every `.js` file your page owns must be loaded with `type="module"`:

```html
<script type="module" src="script.js"></script>
```

Never as a plain classic script. This matches how CrootJS itself is distributed (`import { x } from "https://cdn.jsdelivr.net/gh/crootjs/lib@<version>/module.js"`) and keeps the whole page in strict-mode ES module scope — no accidental globals.

## 3. Import CrootJS from a pinned CDN version

```js
import { getJSON, postJSON } from "https://cdn.jsdelivr.net/gh/crootjs/lib@0.0.27/api.js";
```

- Always pin an exact version tag (`@0.0.5`), never `@latest`, in committed code — `@latest` can silently change behavior under you.
- Import only the specific module files you actually use (`cookie.js`, `url.js`, ...), not the whole library, so the page only loads what it needs.

## 4. No AI slop

Code generated by an AI agent must be as deliberate as hand-written code. These rules are checked in review; breaking one is a reason to reject the change.

1. **Never invent an API.** Before calling any CrootJS function, check its name, parameter order, and options against [llms.txt](https://croot.js.org/llms.txt) or the module's docs page for the pinned version. If what you need does not exist, write it explicitly in your own code — don't guess an option and hope.
2. **Use what CrootJS already has.** `api.js` for requests, `element.js` for DOM by ID, `map.js` for maps, `model3d.js` for 3D, `toast.js` for notifications. Don't re-implement them, and don't add a library that duplicates them (Leaflet, Three.js, axios, jQuery).
3. **No dead weight.** No unused imports, variables, or functions; no commented-out code; no `TODO`/placeholder stubs; no "example" functions nobody calls; no files that aren't needed.
4. **Comments explain why, not what.** Don't narrate each line (`// get the value`, `// import CrootJS`). Comment the reason behind a non-obvious choice, in the same language as the rest of the project.
5. **No fake content.** No lorem ipsum in finished pages, no invented statistics, testimonials, or claims ("trusted by thousands of developers"). Sample data is labelled as sample data.
6. **Handle errors that can actually happen.** Follow each function's contract (e.g. `api.js` reports network failure as `status: 0`); don't wrap everything in `try/catch` that swallows errors, and don't add checks for states that cannot occur.
7. **Stay in scope.** Change only what the task needs. Don't rename, reformat, or restyle unrelated code; don't "improve" things nobody asked about.
8. **Real HTML, not div soup.** Buttons are `<button>`, inputs have `<label>`s, everything works with the keyboard and at phone width. No decoration that wasn't asked for (gradients, emoji, animations).
9. **Verify before saying "done".** Open the page through a local server, check the browser console has no errors, and try the feature — including at phone width and with touch if it's interactive. Say plainly what you did not test.
10. **Pin and minimise dependencies.** Exact version tags only (never `@latest`), and only the modules the page uses.

Quick check before handing work back: *Does every CrootJS call exist as written? Is every line used? Did I run it? Did I change anything I wasn't asked to?*

## Why

- **Maintainable**: a reviewer (human or AI) can look at one file at a time instead of untangling markup, styling, and behavior mashed together.
- **Cacheable**: separate `.css`/`.js` files are cached by the browser independently of the HTML that changes more often.
- **No build step required**: this works with plain `<link>`/`<script type="module">` tags — no bundler needed, consistent with CrootJS's zero-install philosophy.
- **AI-agent friendly**: a coding agent generating or editing a CrootJS page has one unambiguous place to put each kind of code, instead of guessing whether to inline it.

## For AI coding agents

If you (an AI agent) are building or editing a page that uses CrootJS, drop `CLAUDE.md` into the project root — Claude Code (and compatible agents that read a root instructions file) will pick these rules up automatically:

```sh
curl -o CLAUDE.md https://raw.githubusercontent.com/crootjs/lib/main/CLAUDE.md
```

Read it in a browser at [croot.js.org/lib/CLAUDE](https://croot.js.org/lib/CLAUDE).
